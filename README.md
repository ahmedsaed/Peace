# Peace

**An expense tracker that keeps its mouth shut.**

Every record you make lives in one SQLite file on your phone. No account, no server, no sync,
no ads, no analytics — and nothing reaches the network unless you ask it to.

## What it's for

Peace is built around the month, and around the thing you do fifty times a month: type an amount.

The pickers sit at the top and a calculator keypad at the bottom, so the bottom-right key walks the
whole record — account, category, save — and a coffee takes four taps with one thumb. `=` finishes
a sum first if you were adding things up, and the key's label always says which of the three it is
about to do. It works in split-screen too, with a bank notification open beside it, because that is
where records actually get logged.

Everything else in the app exists to make that ledger tell the truth afterwards. Transfers appear
once instead of twice. A refund nets against the thing it reversed rather than inflating both sides
of the month. A credit card reads as money owed rather than an emptied wallet. Percentages on the
analysis ring add up to exactly 100. Search shows the total of *every* match, not of the rows that
fit on screen.

And it stays on your phone. That is the part most of the alternatives get wrong.

## Features

**Recording**
- Calculator keypad — type `120 + 35` and save the answer
- Two-tier categories, so *Coffee* rolls up into *Food* everywhere
- Transfers between your own accounts, written as one atomic pair
- Refunds that net against the purchase they reverse — long-press it and the account and category come with it
- Multi-currency, with the rate stored **per record**: a purchase made when the dollar was fifty pounds stays at fifty forever
- Credit-limit, foreign-transaction and cash-withdrawal fees, per card
- Split-screen is a supported layout, not an edge case

**Making sense of it**
- Records grouped by day, each day netted, with the month's expense, income and running position in the header
- A category ring and a ranked breakdown of where the money went
- Budgets per category, **suggested from what you actually spend** — no blank screen asking for nineteen numbers on day one
- Free-text search across notes, categories and accounts, with filters and a total
- Accounts, with balances derived from the ledger rather than stored
- Balance corrections for when the bank disagrees — they move your position without ever counting as spending

**Less typing** *(optional, off until you add your own API key)*
- Photograph a receipt and have it read into the form — shop, total, and the basket line by line
- Bank notifications captured and offered as records to approve, never written behind your back
- Cash out of an ATM is recognised as a **transfer**, not an expense, so it isn't counted twice
- The finance half of each prompt is yours to edit — "the card ending 0042 is Kenana" resolves against your real accounts

**Keeping it**
- Receipts and PDF invoices attached to records, content-addressed and carried inside the backup
- Backups are a plain zip: `peace.db` beside an `attachments/` folder — unzip it anywhere and your data is there without this app
- **Undo last restore**, because a backup you cannot get back out of is only half a safety net
- Optional Google Drive backup, sealed with a passphrase, where everything needed to open the file travels inside it
- CSV export that carries both legs of a transfer, so per-account balances in the file add up

**Also in the drawer**
- Recurring payments — set while entering the record, then proposed each month for you to approve, edit or dismiss
- Portfolio rebalancing, deliberately not wired into the ledger, which never tells you to sell

## Private by default

The whole app makes **four** outbound calls, and there are no others. Two stay off until you
switch them on, one happens only when you tap a button, and one is a once-a-day version check.

| Talks to | When | Default |
|---|---|---|
| `api.frankfurter.dev` | you tap to fetch an exchange rate | never load-bearing — the field stays manual if it fails |
| `generativelanguage.googleapis.com` | reading a receipt or a bank message | **off** — needs your own Gemini key |
| `googleapis.com/drive` | backup to Drive's private app folder | **off** — needs you to connect it |
| `api.github.com` | checking once a day whether a newer build exists | one quiet line in the drawer, nothing when it fails |

A few things that follow from taking that seriously:

- **No account and no server.** There is nothing to sign up for and nothing to be locked out of.
- **Bank alerts are read, not your inbox.** Android hands over the notification your messaging app
  already showed — the same text you read off a lock screen. No `READ_SMS`, no conversation
  history. The sender list **starts empty and reads nothing** until you name a bank.
- **The microphone is blocked in the manifest.** `RECORD_AUDIO` is on the app's blocked list, so
  the permission cannot be requested even by accident.
- **Your Gemini key lives in the device keystore**, never in the settings table — that table
  travels inside every backup.
- **Disconnecting Drive signs out, it never revokes.** Revoking would make Google delete the app
  folder, so "pause backups" would silently destroy every backup you had.

## Install

**[Download the latest APK from the Releases page.](../../releases/latest)** Every merge to `main`
publishes a signed arm64 build there, and it upgrades an existing install in place — no uninstall,
no data loss.

> [!WARNING]
> **Play Protect blocks this APK, and will keep blocking it.** Peace declares a
> `NotificationListenerService` to read bank alerts, and Google automatically blocks sideloaded
> apps that use notification access. The dialog has no "Install anyway", and it appears on every
> update rather than only the first.
>
> Two ways through, both on the phone's side:
> - `adb install -r peace-<version>-build<n>.apk` — a different install path, not subject to it
> - Pause Play Protect (Play Store → profile → Play Protect → settings), install, switch it back on

<details>
<summary>Why there is no manifest fix for this</summary>

The declaration **is** the capability — Google classes notification access alongside `READ_SMS`
and accessibility services, so no amount of manifest tuning avoids the block while the feature
exists. The real escape is distributing through Play itself, and an internal testing track would
do it: notification access is governed by the ordinary "necessary for core functionality" policy,
not the near-total ban that applies to `READ_SMS`. Keeping that door open is exactly why Peace
reads notifications rather than the inbox.

</details>

Settings → About shows the exact version, build number and commit, so "which build am I running"
is answerable from the phone. A build made from uncommitted code is marked `-dirty`.

## Deliberately not doing

A short list, because what an app refuses to do is as much a description of it as what it does.

| | |
|---|---|
| **Multi-device sync** | The ledger stays on the phone. Sync means a server, an account, and a copy of your spending somewhere you don't control. |
| **Budget carry-over** | An unspent limit rolling into next month is a limit that gets easier every time you fail to use it. What carries between months is *money* — the header's **Now** does that instead, and reconciles exactly with the Accounts total. |
| **Voice entry** | Dropped rather than deferred. Photographing a receipt answers the same question better, and a second capture path would be a second set of parsing rules to keep honest. |
| **One cross-currency total** | Valuing a whole balance needs today's rate, and the only honest rates here belong to past records. Accounts shows one line per currency held instead of one authoritative-looking number. |
| **Settings that do nothing** | A control for a preference nothing reads is a switch that silently lies. Each row ships in the same change as the code that honours it. |
| **The Play Store — for now** | Sideloading is what lets Peace read bank notifications without a restricted-permission review. An internal testing track stays possible; a public listing would mean asking Google's permission to keep the feature. |

There are 27 more decisions like these, each with the reasoning and usually the bug that caused it,
in **[docs/decisions.md](docs/decisions.md)**.

## Under the hood

Expo SDK 57 · React Native 0.86 · React 19.2 · TypeScript · expo-router · NativeWind ·
Drizzle ORM + expo-sqlite · react-native-svg · fflate · Zustand · Jest · Maestro

**992 unit tests** and **20 Maestro end-to-end flows**. No chart library and no UI kit — every icon
and the category ring are hand-drawn SVG paths, which is how the APK avoided 11.7 MB of Skia for a
donut. The one piece of native code is a local Expo module in
[`modules/notification-listener/`](modules/notification-listener): a `NotificationListenerService`
and about four functions.

Money is stored as **integer minor units**, everywhere, converted only at the render boundary.
Balances are derived, never stored. All writes go through `src/db/repo/`, which enforces what
SQLite cannot — category depth, atomic transfer pairs, and which side of the ledger a row is on.

### Building it yourself

```bash
npm install
npm test              # 992 unit tests, no device needed
npm run typecheck
npm run emu           # boot the headless Android emulator
npm start             # Metro dev server
npm run apk           # signed release APK (arm64; apk:emu for x86_64)
```

The toolchain installs entirely under `$HOME` — no sudo, no system packages.
**Read [AGENTS.md](AGENTS.md) before any native build**: it has the environment, the verification
workflow, and the memory constraints that will OOM the machine if you get the order wrong.

Missing signing credentials fall back to debug signing rather than failing, so a fresh clone builds
a working APK. It just is not upgrade-compatible with the released one.

> **Expo has changed.** SDK 57 and RN 0.86 are newer than most training data and most tutorials.
> Read [the versioned docs](https://docs.expo.dev/versions/v57.0.0/) rather than writing APIs from
> memory.
